How PolicyInduction consumes them

No prose conversion. Each row is flattened to column: value lines and handed to the LLM as-is, so it receives the same information the sklearn baselines do.

sex: Male                              Policies:
age_years: 39                          id=0: Defendants with 6 or more prior
age_group: 25 to 45                          offenses are likely to reoffend.
prior_offense_count: 9         +       id=1: ...
juvenile_felony_convictions: 0
current_charge_severity: Felony        → one YES/NO answer per policy id
generate policies→ score each policy × sample→ binary matrix→ L1 logistic regression→ YES / NO

The LLM writes natural-language policies from labelled batches, answers YES/NO for every (policy, sample) pair, and those answers become the binary feature matrix a logistic regression is fitted on. The regression's weights decide which policies matter.

2  How the test is implemented

StepDetail
FilterProPublica's published filter → 6,172 rows
SplitStratified 70/30, random_state=0 → 4,320 / 1,852
TrainFirst 500 training rows (what the LLM method can afford)
TestAll 1,852 rows — identical for every model
BaselinesFitted twice: on all 4,320 and on the same 500
Encodingsklearn: one-hot → 12 cols  ·  PolicyInduction: column: value text

Both methods receive identical inputs, so any difference is attributable to the method rather than to preprocessing. The 500-row baseline rows are the valid head-to-head comparison.
